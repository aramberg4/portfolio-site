Architecture Specification

INSIDER MONITOR PHASE 1

Polymarket Prediction Market — Insider Detection & Alert System
SYS.READY _ v1.0.0-draft 2026.03.01
001 — Overview

Context

News articles regularly surface "insider" prediction market accounts on Polymarket — new wallets created hours before major geopolitical events, placing large directional bets that resolve correctly. The goal is to build a real-time monitoring tool that detects these accounts, computes an insider likelihood score based on 7 weighted signals, and dispatches Discord alerts — enabling manual evaluation and, in future phases, automated copy-trading.

Phase 1 scope: Monitor + Score + Alert only. No auto-trading. No blockchain node required — Polymarket's Data API pre-processes on-chain trades.

# Signal Weight Scoring Logic
01 Wallet Age 0.25 <1 day = 100, <3 days = 90, <1 week = 75, <2 weeks = 55, <1 month = 35, <3 months = 15, older = 5
02 Size vs Liquidity 0.20 Trade USDC / market liquidity ratio. >30% = 100, >10% = 75, >5% = 55, >1% = 20
03 Bet Concentration 0.15 % of portfolio in single market + diversification penalty (fewer unique markets = higher score)
04 Time to Resolution 0.15 <2 hrs = 100, <6 hrs = 90, <24 hrs = 75, <3 days = 55, <1 week = 35
05 Win Rate 0.10 Historical accuracy across resolved bets. Requires ≥5 resolved positions. >85% = 100, neutral if insufficient data
06 Price Impact 0.10 Trade price vs pre-trade midpoint. >15¢ movement = 100, >5¢ = 65, >1¢ = 25
07 Contrarian 0.05 Buying low-probability outcome (<25¢) = 90. Buying high conviction (>85¢) = 60. Neutral = 20

008 — Throttling

Rate Limiting

API Limit Strategy
PolygonScan 4 req/sec (under 5/sec free tier) Queue wallet lookups sequentially. Cache permanently — wallet age never changes.
Data API 2 req/sec (conservative) 1 poll per 5s cycle + queued /positions and /activity calls for enrichment.
Gamma / CLOB 2 req/sec each Heavy caching (15min TTL). Market metadata rarely changes mid-session.
Discord 30 msg/min Queue alerts with 2s spacing. Insider signals are rare enough to stay well under limit.
Retry policy: All API clients implement exponential backoff with jitter on 429/5xx responses. Formula: min(base × 2^attempt + random(0, 1000ms), 60s). Max retries: 3 for enrichment calls, 5 for trade polling.

010 — Resilience

Error Handling

Failure Mode Detection Recovery Strategy
Data API down HTTP 5xx or timeout Exponential backoff, skip cycle. Next poll catches up via watermark.
PolygonScan down HTTP 5xx or timeout Skip wallet age lookup. Use neutral score (50) for that signal.
Gamma/CLOB down HTTP 5xx or timeout Use stale cached values. Market metadata is tolerant of staleness.
Discord webhook fails HTTP 4xx/5xx Queue alert, retry with backoff. Log to alert_log for manual review.
Process crash SIGTERM / uncaught exception Graceful shutdown: stop poller, drain alert queue, close DB. Resume from last watermark on restart.

012 — Roadmap

Future Phase Compatibility

Phase 2
Backtesting
The signals table stores every sub-score for every scored trade. Add a market_resolutions table, query historical accuracy, and tune scoring weights based on precision/recall against real outcomes.
Phase 3
Dashboard
Add a lightweight HTTP server (Hono or Fastify) reading from the same SQLite database. The schema already has all data needed for a signal review UI, wallet leaderboard, and accuracy tracking.
Phase 4
Auto-Trading
New trade-executor service subscribing to high-score signals (≥80) via the @polymarket/clob-client SDK. Proportional position sizing based on confidence and budget. Modular — no changes to existing pipeline.
